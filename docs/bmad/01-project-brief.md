# Project Brief — CGM-diet

**Роль:** Analyst · **Дата:** 2026-08-24 · **Статус:** утверждён

## Проблема

Человек носит CGM-датчик и видит, что сахар скачет. Приложение датчика
показывает **что** происходит с глюкозой, но не **из-за чего**: оно ничего не
знает о еде. Дневники питания, наоборот, считают калории и не знают о глюкозе.
Между двумя приложениями остаётся вопрос, ради которого всё и затевалось:
*«после чего именно у меня поднимается сахар?»*

Ответить на него вручную нельзя: нужно сопоставить десятки приёмов пищи с
тысячами точек глюкозы, учесть базовую линию, отсеять наложившиеся трапезы и
понять, что повторяется, а что случайность.

Параллельная проблема — самочувствие. Сонливость, потливость, туман в голове
одинаково объясняются постменопаузой, преддиабетом, диабетом и обычной
усталостью. Без данных человек либо игнорирует симптомы, либо приписывает их не
той причине.

## Целевой пользователь

**Основной:** взрослый человек с CGM-датчиком, у которого есть основания следить
за углеводным обменом (преддиабет, инсулинорезистентность, диабет 2 типа,
период постменопаузы) и который готов пару минут в день вести дневник.

Ключевая характеристика: он не хочет становиться аналитиком данных. Он хочет
сфотографировать тарелку и через две недели получить список «вот эти три вещи
у вас стабильно дают +3 ммоль/л».

**Вторичный:** лечащий врач или нутрициолог, которому пользователь приносит
выгрузку.

## Что уже есть на рынке

| Класс | Примеры | Чего не хватает |
|---|---|---|
| Приложения CGM | Libre, Dexcom Clarity | не знают о еде |
| Дневники питания с ИИ | mealgram-подобные | не знают о глюкозе |
| Медицинские дневники | FoodShot | считают дозу инсулина — другая, регулируемая ниша |
| Аналитика CGM | cgmquantify, Glucose360 | библиотеки для исследователей, не продукт |

Незанятая позиция: **связка «еда ↔ глюкоза ↔ самочувствие» с честной
персональной статистикой и без медицинских назначений.**

## Ценностное предложение

> Сфотографируй, что ешь, и присылай сахар. Через две недели бот покажет, после
> каких компонентов твоей еды сахар растёт сильнее — с числами, а не с общими
> советами из интернета.

## Границы

**В продукте:** приём любого формата ввода; связывание еды и глюкозы по времени;
статистика по компонентам с уровнем достоверности; проверка продукта перед
покупкой; опрос самочувствия; графики; экспорт и удаление данных; активность из
Samsung Health.

**Не в продукте (сознательно):** дозы инсулина и любых препаратов, диагнозы,
интерпретация анализов, планы питания «на неделю», социальные функции,
рекомендации по обследованиям.

## Риски

| Риск | Митигация |
|---|---|
| Пользователь перестанет вести дневник через неделю | минимум нажатий; ввод в любом виде; голос; ранние промежуточные выводы |
| Данных не хватит на выводы | статистика по компонентам, а не по блюдам — выборка растёт кратно быстрее |
| Ложные выводы на малой выборке | пороги достоверности, группа сравнения, отказ показывать вывод |
| Регуляторные риски (медизделие) | ни диагнозов, ни назначений, ни доз; конституция проекта, тест на формулировки |
| Ошибки распознавания | подтверждение каждого значения, сохранение исправлений |
| Стоимость vision-вызовов | детерминированный парсер текста без модели; один классификатор вместо четырёх вызовов |

## Критерии успеха

1. Через 14 дней у активного пользователя есть ≥ 1 компонент с достоверностью
   «средняя» или выше.
2. ≥ 60 % приёмов пищи попадают в статистику (есть базовая линия и точка в окне).
3. Запись еды по фото — не более двух нажатий.
4. Ноль сообщений с медицинскими назначениями (проверяется тестом и ревью).
