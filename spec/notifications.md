# notifications — напоминания: админ задаёт, человек уточняет, «умное» считает

Одна модель напоминаний на обе поверхности: веб (web push) и бот (сообщение в
чат). Текст напоминания задаёт админ/владелец, каждый пользователь может
переопределить время и вид, а режим «умное» вычисляет время из собственных
записей человека.

Источники: `web/lib/notifications.php`, `web/api/notify_config.php`,
`web/api/push_send.php`, `web/app/js/notify.js`, `web/app/sw.js`,
`web/admin/index.php` § Уведомления;
`src/analytics/notify.py`, `src/db/models.py` (`notification_templates`,
`notification_prefs`, `notification_sends`), `src/handlers/notify.py`,
`src/handlers/notify_admin.py`, `src/scheduler.py`.

## Шаблон уведомления (задаёт админ)

```
TABLE notification_templates
  id INT · code TEXT UNIQUE · title TEXT · body TEXT
  action TEXT     camera|text|open — что открывается по нажатию
  mode TEXT       fixed|smart|off  — режим по умолчанию для всех
  times TEXT      CSV «HH:MM», локальное время пользователя
  signal TEXT     CSV meal|glucose|activity|weight|wellbeing — чем кормить «умное»
  lead_min INT    за сколько минут до привычного момента писать (по умолчанию 15)
  enabled INT · sort INT · updated_at TEXT
```

`title` и `body` — свободный текст: админ пишет, что человек увидит.
Встроенных текстов в коде нет, кроме сидов при первом создании базы
(`meal` — «Запишите приём пищи», `cgm` — «Пришлите скриншот датчика»).

Клинические правила формулировок (`spec/clinical.md`) действуют и здесь:
напоминание зовёт записать, а не ставит диагноз и не обещает эффект.

## Настройка пользователя

```
TABLE notification_prefs
  web: client_id TEXT · code TEXT · mode TEXT · times TEXT · tz_offset INT · updated_at
  bot: user_id INT · code TEXT · mode TEXT · times TEXT · updated_at
  UNIQUE(client_id|user_id, code)
```

`mode` пользователя: `default` (как настроил админ) · `fixed` (своё время) ·
`smart` (умное) · `off` (выключено).

**Приоритет**: шаблон админа — исходное состояние; запись пользователя
перекрывает его там, где она есть. Нет записи или `mode=default` — действует
шаблон. `enabled=0` у шаблона выключает уведомление у всех независимо от
пользовательских настроек: выключенного уведомления нет ни у кого.

Разрешение (`resolve_schedule`):

```
effective(template, pref) -> (mode, times)
  template.enabled = 0                  -> ('off', [])
  pref is None or pref.mode = 'default' -> (template.mode, template.times)
  pref.mode = 'fixed'                   -> ('fixed', pref.times or template.times)
  pref.mode = 'smart'                   -> ('smart', smart_times(...) or template.times)
  pref.mode = 'off'                     -> ('off', [])
```

## «Умное» время (`src/analytics/notify.py`, `web/app/js/notify.js`)

Вход — минуты суток (локальные) всех записей тех видов, что перечислены в
`signal` шаблона; классификация по виду записи уже произошла при её создании
(еда → `meal`, замер/скриншот CGM → `glucose`, тренировка и ходьба →
`activity`, вес → `weight`, самочувствие → `wellbeing`).

```
smart_times(minutes:list[int], *, slots:int, lead_min:int,
            min_events:int=6, min_cluster:int=2, window_days:int=21) -> list[str]
```

1. берутся записи за последние `window_days` дней; меньше `min_events` —
   возвращается пустой список (и вызывающий берёт время шаблона: выдумывать
   привычку по трём точкам нечестно);
2. минуты суток кластеризуются одномерным k-means, `k = slots`, начальные
   центры — квантили выборки, до 25 итераций, детерминированно;
3. кластер меньше `min_cluster` записей отбрасывается — случайный поздний
   ужин не становится ежедневным уведомлением;
4. время кластера = **медиана** его минут (устойчива к выбросам) минус
   `lead_min`, округление вниз до 5 минут, перенос через полночь по модулю
   1440;
5. результат сортируется и отдаётся как `HH:MM`.

`slots` = сколько уведомлений в день: у еды — `meals_per_day` профиля (бот) /
`profile.mealsPerDay` (web), иначе число времён в шаблоне, иначе 3.

## Отправка

### web (cron → `api/push_send.php?key=<CRON_SECRET>`)

Тик (хостинговый cron, раз в 5–15 мин) по каждой подписке с
`reminders_enabled=1`:

1. локальное время подписки = UTC + `tz_offset` (минуты, приходит от клиента
   вместе с настройками);
2. для каждого включённого шаблона — `effective(...)`; слот считается
   наступившим, если локальное «сейчас» попало в `[t, t+SEND_WINDOW_MIN)`
   (`SEND_WINDOW_MIN = 30`) — редкий cron не должен терять уведомление;
3. дубль отсекает `notification_sends UNIQUE(client_id, code, slot, sent_on)`,
   где `sent_on` — **локальная** дата: строка вставляется до отправки, сбой
   сети не превращается в второе уведомление;
4. payload: `{title, body, code, action}`.

Кнопка «Отправить сейчас» в админке шлёт выбранный шаблон всем подписчикам
мимо расписания и мимо `notification_sends`.

### бот (`src/scheduler.py`, `notification_loop`, тик 300 с)

То же разрешение расписания, локальное время — из `users.tz`. Дубль отсекает
`notification_sends UNIQUE(user_id, code, slot, sent_on)`; отметка ставится до
`send_message`, как у остальных напоминаний бота.

## Нажатие на уведомление

| action | web | бот |
|---|---|---|
| `camera` | `sw.js` открывает `/app/?n=<code>&act=camera` → сразу камера | кнопка «📷 Сфотографировать» — подсказка прислать фото |
| `text` | открывает экран ввода текста | кнопка «✍️ Ответить текстом» |
| `open` | открывает приложение | обычное сообщение |

У web-уведомления две кнопки независимо от `action`: «📷 Сфотографировать» и
«✍️ Ответить» (последняя — inline-поле ввода там, где браузер его
поддерживает: `NotificationAction.type = 'text'`; где нет — открывает экран
ввода в приложении). Ответ уходит в приложение как `?n=<code>&act=text&reply=…`.

### Ответ текстом → «мои блюда»

Текст ответа сперва ищется среди «моих блюд» (`spec/dictionary.md`), и только
если ничего не нашлось — уходит в модель:

```
match_dish(text) -> entry | None
  точное совпадение по key_norm
  → префикс (единственный кандидат)
  → подстрока (единственный кандидат)
  → пересечение слов ≥ 2 и единственный кандидат
```

Неоднозначность (два кандидата) — не догадка: показываем список и даём
выбрать. Совпадение открывает карточку подтверждения с весом и БЖУК из
памяти, без обращения к модели; ничего не нашлось — текст уходит обычным
путём распознавания (`spec/ingest.md`).

## Админка

`web/admin/index.php` § Уведомления: таблица шаблонов, у каждого — `title`,
`body`, время (CSV), режим, действие, сигналы для «умного», `lead_min`,
включён ли; «Добавить», «Удалить», «Отправить сейчас». Бот: `/notify_admin`
у владельца — те же поля, правка текстом.

Пользователь: web — «Настройки → Уведомления»; бот — `/notify`.
