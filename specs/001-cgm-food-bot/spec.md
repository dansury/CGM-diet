# Feature Specification: Дневник «еда → сахар → самочувствие»

**Feature Branch**: `001-cgm-food-bot`
**Created**: 2026-08-24
**Status**: Implemented (MVP)
**Input**: Телеграм-бот, который принимает фото еды, скриншоты CGM, анализы и
текст в любом виде, связывает приёмы пищи с глюкозой по времени и находит
статистические закономерности: после каких компонентов блюд у конкретного
человека поднимается сахар.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Записать еду за один жест (Priority: P1)

Пользователь фотографирует тарелку и отправляет фото. Бот распознаёт блюда,
оценивает порции и БЖУК, показывает карточку и просит подтвердить.

**Why this priority**: без потока «еда» нет данных, из которых строится всё
остальное. Это единственная функция, которую пользователь выполняет 3–5 раз в день,
поэтому цена лишнего нажатия здесь максимальна.

**Acceptance**:
1. Фото без подписи → карточка с блюдами, порциями и итогами БЖУК ≤ 15 с.
2. «✅ Верно» → запись в `meals`/`meal_items`, ноль дополнительных вопросов.
3. «✏️ Исправить» → строка вида `гречка 250, курица 100` пересчитывает порции и
   нутриенты, старое значение сохраняется в `corrections`.
4. Фото не еды → бот сам определяет тип и переключается, либо предлагает 4 кнопки.

### User Story 2 — Показать, после чего растёт сахар (Priority: P1)

Пользователь открывает `/stats` и видит компоненты блюд, отсортированные по
среднему подъёму сахара, с числом наблюдений и уровнем достоверности.

**Acceptance**:
1. Для каждого ключа показаны n, среднее, медиана, максимум, сравнение «без
   этого компонента», p-value.
2. Ключ с n < 3 не показывается вообще.
3. Достоверность «высокая» только при n ≥ 8, CI выше нуля, p < 0.05 и среднем
   подъёме ≥ 1.5 ммоль/л.
4. В тексте нет причинно-следственных утверждений.

### User Story 3 — Проверить продукт перед покупкой (Priority: P2)

В магазине пользователь включает режим «🛒 Проверить продукт», снимает упаковку
(одно или два фото) и получает ответ по своей собственной статистике —
без записи в дневник как съеденного.

**Acceptance**:
1. Два фото одним альбомом объединяются в одну карточку продукта.
2. Ответ ссылается на конкретные наблюдения пользователя либо честно говорит,
   что данных пока нет.
3. Кнопка «🍽 Я это съел(а)» превращает продукт в приём пищи с редактируемой
   порцией; продукт запоминается по названию и штрихкоду.

### User Story 4 — Отметить самочувствие (Priority: P2)

Пользователь оценивает состояние 1–5. Если не 5 — выбирает симптомы кнопками из
своего личного глоссария, дописывает или наговаривает новые.

**Acceptance**:
1. Оценка 5 закрывает диалог сразу, без списка симптомов.
2. Глоссарий сортируется по частоте использования этим пользователем.
3. Новый симптом (текстом или голосом) добавляется в глоссарий и появляется
   кнопкой в следующий раз.
4. `/stats` показывает контраст: сахар в момент симптома против остальных отметок.

### User Story 5 — Ввод «в любом виде» (Priority: P2)

«сахар 8», «гк 130 mg/dl в 8:30», «вчера в 21:00 сахар 9.1, вес 72,3»,
голосовое, PDF с анализами, скриншот CGM.

**Acceptance**:
1. Показатели крови, вес, лекарства, оценка самочувствия и время извлекаются
   без вызова модели.
2. Остаток текста уходит в разбор еды.
3. mg/dL и ммоль/л распознаются и конвертируются; спорный диапазон 18–33
   решается кнопкой «Сменить единицы».

### User Story 6 — Влияние активности (Priority: P3)

Приложение-мост на телефоне отдаёт шаги из Samsung Health / Health Connect;
бот сравнивает подъём после еды с прогулкой и без.

### Edge Cases

- Две трапезы подряд внутри окна → экскурсия помечается contaminated и
  исключается из статистики.
- Нет измерений сахара в окне → приём пищи хранится, но в статистику не входит.
- Скриншот без даты → берётся сегодняшнее число, будущее время откатывается на сутки.
- PDF без текстового слоя → бот просит фото страницы.
- Модель недоступна → сообщение об ошибке и предложение ввести текстом; данные не теряются.

## Requirements *(mandatory)*

### Functional

- **FR-001**: приём фото, альбомов, документов (PDF/изображения), голоса и текста.
- **FR-002**: автоклассификация фото на 4 типа + ручное переключение.
- **FR-003**: подтверждение/исправление любого распознанного значения до записи.
- **FR-004**: связывание еды и глюкозы по настраиваемым окнам (45–90, 90–150 мин).
- **FR-005**: статистика по компонентам, блюдам и продуктам: n, среднее, медиана,
  максимум, CI, контраст, p-value, уровень достоверности.
- **FR-006**: CGM-метрики: TIR/TAR/TBR, CV, GMI, eA1c, LBGI/HBGI, MAGE, J-index.
- **FR-007**: опрос самочувствия с динамическим глоссарием симптомов.
- **FR-008**: графики: таймлайн, рейтинг компонентов, самочувствие.
- **FR-009**: `/today`, `/stats`, `/graph`, `/export`, `/delete`, `/health`, `/settings`.
- **FR-010**: приём активности через HTTP-релей с per-user токеном.
- **FR-011**: mock-режим без сети и ключей.

### Non-functional

- **NFR-001**: ответ на фото ≤ 15 с при доступной модели.
- **NFR-002**: полная работоспособность на SQLite (личный инстанс) и PostgreSQL.
- **NFR-003**: удаление данных — необратимое и полное.
- **NFR-004**: ни одно медицинское назначение не может быть выдано (см. конституцию).

### Key Entities

`users`, `meals`, `meal_items`, `glucose_readings`, `weights`, `medications`,
`analysis_results`, `media_files`, `products`, `product_photos`, `symptoms`,
`wellbeing_checkins`, `checkin_symptoms`, `activity_samples`, `food_stats`,
`corrections`.

## Success Criteria

- **SC-001**: через 14 дней ведения дневника у пользователя есть хотя бы один
  компонент с достоверностью «средняя» или выше.
- **SC-002**: доля приёмов пищи, попавших в статистику (есть baseline и точка в
  окне), ≥ 60 %.
- **SC-003**: запись приёма пищи по фото — не более двух нажатий.
- **SC-004**: `/export` открывается в Excel без ручной правки кодировки.
