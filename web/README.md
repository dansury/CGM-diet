# web — деплой на PHP-хостинг

Спецификация: `../spec/web.md`. Ниже — только шаги деплоя.

## Требования хостинга

PHP ≥ 8.1 (нужен `openssl_pkey_derive` для web push), расширения `pdo_sqlite`,
`curl`, `openssl`. Composer не нужен — весь `web/` самодостаточен, сборки нет.

## Деплой

1. Скопируйте содержимое `web/` целиком в корень (или подкаталог) хостинга —
   обычным FTP/SFTP/файловым менеджером. Никакой сборки не требуется.
2. Убедитесь, что каталог **рядом** с корнем сайта доступен на запись: база
   `app.db` создаётся в `<родитель корня>/cgm-diet-data`, чтобы следующая
   заливка не стёрла ключи и настройки моделей. Если родитель на запись
   недоступен, задайте `WEB_DATA_DIR` (или `WEB_DB_PATH`) на любой каталог вне
   `web/`; в самом крайнем случае используется `web/data` — тогда админка
   покажет предупреждение, что настройки переживут не каждую заливку.
   Существующий `web/data/app.db` при первом запросе копируется на новое
   место — настройки не теряются.
3. Откройте `https://ваш-домен/admin/` — при первом заходе будет предложено
   задать пароль администратора.
4. В админке заполните: `OPENROUTER_API_KEY` (или `YANDEX_API_KEY` +
   `YANDEX_FOLDER_ID`), модель по умолчанию, `ADMIN_EMAIL` (используется как
   VAPID `subject` для push). Нажмите «Перегенерировать VAPID», если хотите
   включить напоминания.
5. Для уведомлений по расписанию настройте cron хостинга (обычно — в панели
   управления) на вызов **каждые 5–15 минут**:
   `curl "https://ваш-домен/api/push_send.php?key=<CRON_SECRET>"`
   (ключ — из раздела «Push-уведомления» в админке). Каждый вызов — один тик:
   отправляется то, чьё время наступило, в местном времени каждого человека;
   повтор в тот же слот того же дня отсекается. Реже 30 минут — уведомления
   начнут теряться. Без крона всё можно разослать вручную кнопками «Прогнать
   расписание сейчас» и «Отправить сейчас» у нужного уведомления.
6. В разделе «Уведомления» задайте, что и когда приходит: заголовок, текст,
   время, режим по умолчанию и что открывается по нажатию. Это исходная
   настройка для всех — каждый человек может поменять её у себя в приложении
   («Настройки → Уведомления»), включая режим «умное»: время подбирается по
   его собственным записям на устройстве.
7. Проверьте `https://ваш-домен/` (лендинг) и `https://ваш-домен/app/`
   (приложение) — оба должны открыться без ошибок в консоли браузера.
8. В админке нажмите «Проверить модели и ключи»: каждая настроенная модель
   получит короткий запрос, ответ провайдера показывается строкой. Что-то не
   так — раздел «Лог» внизу страницы копируется одной кнопкой (ключи в тексте
   замаскированы); лог очищается сам при следующей заливке кода.

## Проверки перед заливкой

```
php -l $(find web -name '*.php')     # синтаксис
php web/tests/notifications.php      # расписание уведомлений и учёт отправок
```

## Обновление LLM-инфраструктуры

`web/lib/vendor/*` — зеркало репозитория `site_yacloud_openrouter`, не
редактируется на месте (`web/lib/vendor/VENDORED_FROM.md`). Чтобы подтянуть
новую версию: скопировать `llm.php`, `config.php`, `settings_store.php`,
`model_catalog.php`, `diag_log.php` из `site_yacloud_openrouter` поверх файлов
в `web/lib/vendor/`, обновить дату/коммит в `VENDORED_FROM.md`,
перезадеплоить.

## Иконки PWA

`web/app/icons/*.png` рисует `scripts/gen_app_icons.py` (только стандартная
библиотека, зависимостей нет) — тот же кочан романеско, что и в интерфейсе.
Перегенерировать: `python scripts/gen_app_icons.py`. Размеры и имена файлов
менять не нужно, `manifest.webmanifest` на них уже ссылается.

## Шрифт

`web/assets/fonts/electrolize.woff2` — Electrolize (SIL OFL), тот же
дисплейный шрифт, что на `dansury.github.io`. Лежит в репозитории, снаружи не
подгружается: приложение должно открываться офлайн. Inter для интерфейсного
текста лендинг берёт из Google Fonts, у приложения — системный фолбэк.
